10. PLANNED: SLACK FOR THE MANAGER ("AdministrationCloudManager")
--------------------------------------------------------------------------------------
Goal: the manager agent chats with the owner over Slack as well as Telegram, same policy, same
approvals, same task notifications.
- Create a new Slack app/bot integration for it (a bot user named AdministrationCloudManager).
  Prefer Socket Mode (the app opens the connection outbound; no public webhook, same shape as the
  Telegram long poll) so nothing needs to be exposed on the network.
- Request the install in the company Slack workspace (the workspace's app-approval / admin request
  process). Expect a security or data-handling review: say what it reads (direct messages to the bot
  and mentions only), what it can post, and that it never reads channel history it is not part of.
  Find out whether the workspace needs an admin approval, an Enterprise Grid org-level approval, or
  an allow-listed app directory entry.
- Minimal scopes to start with: chat:write, im:history, im:read, im:write, app_mentions:read,
  users:read (to resolve the owner), commands only if slash commands are wanted. Nothing else.
  Review before adding anything (files:write for evidence uploads is a later, separate request).
- Tokens: a bot token and an app-level token (Socket Mode). Store them as 0600 files outside any
  mounted container path, plus an entry in the password manager. Never in the repository, logs or
  chat. Plan their rotation.
- Owner pairing, as for Telegram: only the paired Slack user id may talk to it, only in a direct
  message (ignore everything else), pairing by a one-time code that expires.
- Approvals: use interactive buttons (Approve / Deny with the capability, a redacted input summary
  and the budget) instead of /approve commands; same rules (write needs approval, default deny,
  expiry, in-memory so a restart means denied). Task results, questions and agent messages go to
  the same thread as the request.
- Refactor the manager so the chat side is a channel interface (Telegram and Slack implement it);
  the gateway, policy, rate limits, notifier and state stay shared. Keep the redaction rules
  (tokens and long strings never posted).
- Behaviour to decide: one thread per task, how long-running tasks report progress, how much of a
  result is posted (summaries and links, never raw task content), and whether the bot may be added
  to a team channel for read-only status.
- Tests: a fake Slack (Socket Mode events + Web API) in the test suite, pairing and DM-only
  enforcement, button approval round trip, no-leak checks. Then a real smoke test in a private
  test channel before DMs.
- Data governance: messages pass through a third-party service. Decide what the manager may say in
  Slack (identifiers, states, short summaries) and keep source code and secrets out.
